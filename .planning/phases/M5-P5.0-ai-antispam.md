# Phase 5.0 — AI Anti-Spam Engine (On-Device)
_Milestone: M5 | Estimated effort: 12–15 days_

## Goal
Build an on-device ML inference pipeline for spam/phishing/malware classification.
All inference runs locally — no message content leaves the server. The engine
supplements (never replaces) the classic scoring pipeline from Phase 4.

## Design Principles
1. **Fail open**: ML inference failure → pass to next layer, never reject mail
2. **Latency budget**: p99 < 80ms per message; p50 < 20ms
3. **Privacy**: Raw message content never logged or exfiltrated; only feature vectors
4. **Updatable**: Models hot-swappable without restart
5. **Explainable**: Confidence score + top contributing features logged

## Phase 5.1 — Feature Extraction

### 5.1.1 — Feature engineering pipeline
**New package**: `internal/ai/features/`

```go
type FeatureVector struct {
    // Header features
    HasMessageID         float32
    HasDate              float32
    DateOffsetHours      float32  // hours from now (negative = past)
    ReceivedHopCount     float32
    ReceivedMaxDelay     float32  // max delay between hops in minutes
    HeloMatchesPTR       float32
    SubjectLength        float32
    SubjectAllCaps       float32  // fraction of uppercase chars
    SubjectExclamation   float32  // count of "!"
    SubjectHasRe         float32
    FromDisplayHasURL    float32
    ReplyToDomainDiffers float32
    XMailerPresent       float32
    XMailerSpamIndex     float32  // known spam XMailer hash index
    MIMEVersionPresent   float32
    // ...50 total header features

    // Content features (TF-IDF top tokens normalized)
    ContentTokens [200]float32  // sparse representation of top-N spam tokens

    // Structural features
    MIMEPartsCount       float32
    HasHTMLPart          float32
    HasTextPart          float32
    HTMLTextRatio        float32
    HasAttachment        float32
    AttachmentTypeRisk   float32  // scored by extension: .exe=1.0, .pdf=0.3, .jpg=0.0
    ImageOnlyBody        float32  // image spam: body is only <img> tags
    ExternalLinksCount   float32
    LinkTextMismatch     float32  // link display text ≠ href domain

    // Behavioral/envelope features
    RecipientCount       float32
    FromEqualsReplyTo    float32
    IsAuthenticatedUser  float32
    SPFScore             float32  // pass=0, softfail=0.5, fail=1.0
    DKIMScore            float32
    DMARCScore           float32
}
```

Build a tokenizer for the content features using a pre-built vocabulary of 10,000
spam-indicative tokens (trained from SpamAssassin corpus). Store vocabulary as a
compiled Go map (`map[string]int`) embedded via `//go:embed`.

### 5.1.2 — Token vocabulary builder (offline tool)
**New cmd**: `cmd/build-vocab/main.go`

Reads SpamAssassin public corpus (`easy_ham`, `spam`), builds TF-IDF weighted
vocabulary of top-10000 spam-indicative unigrams + bigrams. Outputs a serialized
`vocab.bin` embedded in the binary. Run offline; commit output to repo.

## Phase 5.2 — Model Integration

### 5.2.1 — FastText classifier (primary, fastest)
**Library**: Pure Go FastText inference via pre-trained model

Facebook FastText provides compact (1–50MB) supervised text classifiers.
Pre-train on SpamAssassin + TREC 2007 corpus (700K messages):
- Labels: `__label__spam`, `__label__ham`
- Model: word n-grams (1-2), dim=100, epoch=25, loss=softmax

Load as a Go binary via `//go:embed model/fasttext_spam.bin`.

Pure Go inference implementation (no CGo):
```go
type FastTextModel struct {
    vectors map[string][]float32  // word → embedding
    weights []float32             // output layer
    labels  []string
}

func (m *FastTextModel) Predict(tokens []string) (label string, prob float32)
```

Inference: average word vectors, dot product with output weight matrix, softmax.
Latency: **< 2ms** on a 100KB message.

### 5.2.2 — Gradient Boosting (XGBoost via ONNX Runtime)
**Library**: `github.com/yalue/onnxruntime_go`

Train XGBoost on the structured `FeatureVector` (not text). Export to ONNX format.
ONNX Runtime provides a CGo-free inference path via the pre-built shared library.

```go
type ONNXClassifier struct {
    session *onnxruntime_go.Session
    // Input: [1, 300] float32 feature vector
    // Output: [1, 2] float32 [ham_prob, spam_prob]
}

func (c *ONNXClassifier) Score(features *FeatureVector) (float32, error) {
    inputData := featureVectorToSlice(features)
    input := onnxruntime_go.NewTensor(shape, inputData)
    outputs, err := c.session.Run([]*onnxruntime_go.Tensor{input})
    return outputs[0].GetData()[1], err  // spam probability
}
```

Model size: ~2MB ONNX. Latency: **< 8ms** p99.

Fallback: if `onnxruntime_go` CGo is unavailable (e.g., musl libc containers),
implement a pure-Go decision tree scorer from the exported ONNX nodes using
a simple tree walker.

### 5.2.3 — DistilBERT-tiny deep classifier (async, high-confidence)
**Model**: `distilbert-base-uncased` fine-tuned on spam, quantized INT8
**Interface**: Rspamd sidecar OR Ollama local API

This model is **not** run synchronously on the SMTP DATA path (too slow for p99).
Instead:
1. Message is accepted/tagged by fast models during SMTP
2. Deep model runs async in a background worker pool
3. If deep model returns `spam_prob > 0.95`, message is moved from INBOX to Spam
   (using IMAP STORE + MOVE) and an audit log entry created

```go
type AsyncDeepClassifier struct {
    queue    chan *ClassificationJob
    rspamdClient *RspamdClient  // REST API to local rspamd
}

type ClassificationJob struct {
    MessageID string
    Username  string
    Mailbox   string
    Data      []byte
    ResultCh  chan<- ClassificationResult
}

func (c *AsyncDeepClassifier) SubmitAsync(job *ClassificationJob)
func (c *AsyncDeepClassifier) Start(workers int)
```

**Rspamd integration** (recommended for the deep model layer):
Rspamd runs as a local sidecar (same pod). Communication via HTTP REST API:
```
POST http://localhost:11333/checkv2
Content-Type: message/rfc822
[raw message body]

Response: {"score": 4.2, "action": "add header", "symbols": {...}}
```

This allows leveraging Rspamd's:
- Bayes classifier (with per-user learning)
- Fuzzy hash storage (shared across cluster via Redis)
- Neural network module (Rspamd neural)
- URL reputation
- DKIM/SPF/DMARC integration

### 5.2.4 — Ensemble combiner
```go
type EnsembleScorer struct {
    fasttext *FastTextModel
    onnx     *ONNXClassifier
    weights  EnsembleWeights
}

type EnsembleWeights struct {
    FastText float32  // 0.35
    ONNX     float32  // 0.65
}

func (e *EnsembleScorer) Score(ctx context.Context, features *FeatureVector, tokens []string) (float32, error) {
    ftScore, _ := e.fasttext.Predict(tokens)
    onnxScore, _ := e.onnx.Score(features)
    combined := e.weights.FastText*ftScore + e.weights.ONNX*onnxScore
    return combined, nil
}
```

## Phase 5.3 — Phishing Detection

### 5.3.1 — Domain lookalike detection
**New file**: `internal/ai/phishing/lookalike.go`

Detect homograph and typosquatting attacks:

```go
// Confusable character mapping (Unicode homographs)
// "рaypal.com" (Cyrillic р) vs "paypal.com" (Latin p)
func DeconfuseUnicode(s string) string  // map confusables to ASCII canonical

// Edit distance for typosquatting
func LevenshteinDistance(a, b string) int

// Compare against known brand domains list
type BrandProtectionList struct {
    brands []string  // "paypal.com", "apple.com", "google.com", "microsoft.com"...
}

func (b *BrandProtectionList) IsSuspicious(domain string) (bool, string, float64) {
    canonical := DeconfuseUnicode(domain)
    for _, brand := range b.brands {
        dist := LevenshteinDistance(canonical, brand)
        if dist > 0 && dist <= 2 {
            return true, brand, float64(dist)
        }
    }
    return false, "", 0
}
```

Brand list: embed a curated list of top-500 brands' domains (`//go:embed data/brands.txt`).
Update quarterly.

### 5.3.2 — URL shortener expansion
**New file**: `internal/ai/phishing/url_expander.go`

Known shortener domains (`bit.ly`, `t.co`, `tinyurl.com`, etc.):
- Follow 301/302 with HEAD request (no body download)
- 2-hop maximum, 2s timeout
- Check final domain against URIBL and brand protection list
- Cache expansions for 1 hour

### 5.3.3 — HTML structure analysis
Score HTML messages for phishing signals:
- Single-link body (entire email is one clickable image or link)
- Form fields (`<input type="password">`) in HTML email
- External resource loading from non-sender domain
- CSS visibility tricks (hidden text, white-on-white)
- Excessive URL redirect chains

## Phase 5.4 — Continuous Learning

### 5.4.1 — Per-user Bayesian learning (Rspamd)
Via Rspamd's `learn_spam` / `learn_ham` REST endpoints:
```
POST http://localhost:11334/learnspam  (protected admin port)
POST http://localhost:11334/learnham
```

Wire user feedback:
- IMAP MOVE to Spam folder → `learn_spam`
- IMAP MOVE from Spam to Inbox → `learn_ham`
- Explicit "Mark as Spam" action via JMAP or IMAP flag → `learn_spam`

### 5.4.2 — Model performance monitoring
Track per-day metrics in Elasticsearch:
- False positive rate (spam moved to inbox by user)
- False negative rate (ham moved to spam by user)
- Score distribution histogram
- Top contributing features per decision

Alert (Prometheus/Alertmanager) when:
- FP rate > 0.1% over 24h
- FN rate > 2% over 24h
- Model inference p99 > 100ms
