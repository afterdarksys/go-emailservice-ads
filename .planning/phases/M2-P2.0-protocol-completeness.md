# Phase 2.0 — Protocol Completeness
_Milestone: M2 | Estimated effort: 8–10 days_

## Goal
Fix all RFC non-conformances that break interoperability with standard mail clients
and receiving MTAs. After this phase, the server must pass real-world compatibility
testing with Thunderbird, Apple Mail, Outlook, and common receiving MTAs.

## Success Criteria
- [ ] IMAP UIDVALIDITY persists across server restarts (stored in SQLite/Postgres)
- [ ] IMAP UIDs are monotonically increasing and never reused
- [ ] IMAP SEARCH executes real criteria evaluation (date, from, subject, flags, size)
- [ ] IMAP flag updates (STORE) and EXPUNGE persist
- [ ] Sieve scripts execute (fileinto, reject, vacation, flags)
- [ ] JMAP Email/get returns actual stored messages with correct bodyValues
- [ ] JMAP Bearer token validates JWT from configured issuer
- [ ] SMTP DATA timeout is ≥ 5 minutes
- [ ] SPF `redirect` modifier is handled
- [ ] DMARC `sp=`, `pct=`, `adkim=`, `aspf=` tags are parsed and respected

## Phase 2.1 — IMAP Persistence Fixes

### 2.1.1 — Persistent UIDVALIDITY and UID tracking
**File**: `internal/imap/mailbox.go`, `internal/storage/`

The IMAP spec requires UIDVALIDITY to be an unsigned 32-bit integer that increases
monotonically and NEVER decreases for the lifetime of the mailbox. It must survive
restarts.

Add to storage schema:
```sql
CREATE TABLE IF NOT EXISTS mailbox_state (
    username    VARCHAR(255) NOT NULL,
    mailbox     VARCHAR(255) NOT NULL,
    uidvalidity BIGINT NOT NULL DEFAULT 1,
    uidnext     BIGINT NOT NULL DEFAULT 1,
    PRIMARY KEY (username, mailbox)
);

CREATE TABLE IF NOT EXISTS message_flags (
    msg_id    VARCHAR(255) PRIMARY KEY,
    username  VARCHAR(255) NOT NULL,
    mailbox   VARCHAR(255) NOT NULL,
    uid       BIGINT NOT NULL,
    flags     TEXT[] NOT NULL DEFAULT '{}',
    deleted   BOOLEAN NOT NULL DEFAULT FALSE
);

CREATE INDEX IF NOT EXISTS idx_msgflags_mailbox ON message_flags(username, mailbox);
CREATE INDEX IF NOT EXISTS idx_msgflags_uid ON message_flags(uid);
```

`GetUIDValidity(ctx, username, mailbox)` — fetch from DB, create row if absent
(initial value = `time.Now().Unix()` only on first creation).

`AllocateUID(ctx, username, mailbox)` — atomic `UPDATE mailbox_state SET uidnext = uidnext + 1 RETURNING uidnext - 1`.

### 2.1.2 — Implement SEARCH criteria evaluation
**File**: `internal/imap/mailbox.go:174-188`

Full SEARCH support for RFC 3501 §6.4.4 criteria:
- `ALL`, `ANSWERED`, `DELETED`, `FLAGGED`, `NEW`, `OLD`, `RECENT`, `SEEN`, `UNANSWERED`, `UNDELETED`, `UNFLAGGED`, `UNSEEN`
- `BEFORE date`, `ON date`, `SINCE date`, `SENTBEFORE`, `SENTON`, `SENTSINCE`
- `LARGER n`, `SMALLER n`
- `HEADER field-name string`, `SUBJECT string`, `FROM string`, `TO string`, `CC string`, `BCC string`, `TEXT string`, `BODY string`
- `UID seqset`
- `NOT criterion`, `OR criterion criterion`

Build a `searchMatcher` function that evaluates the `*imap.SearchCriteria` tree
against a fetched message. For text-based criteria, use case-insensitive substring
matching (IMAP4 §6.4.4 default).

### 2.1.3 — Implement STORE (flag updates) and EXPUNGE
**File**: `internal/imap/mailbox.go:223-246`

`UpdateMessagesFlags`: Persist to `message_flags` table. Apply set/add/remove ops.
`Expunge`: `DELETE FROM message_flags WHERE username=$1 AND mailbox=$2 AND deleted=TRUE`.
Send untagged `* N EXPUNGE` responses (handled by go-imap if the store persists correctly).

### 2.1.4 — IDLE support (RFC 2177)
The `go-imap` library supports IDLE via the `backend.MailboxSubscriber` interface.
Implement a pub/sub notification channel per mailbox. When a new message is stored
via `deliverLocal`, publish to the mailbox's notification channel. Waiting IDLE clients
will receive `* N EXISTS` updates.

Use a `sync.Map` keyed by `username/mailbox` storing `[]chan struct{}`.

## Phase 2.2 — Sieve Execution Engine

### 2.2.1 — Integrate a real Sieve interpreter
The custom `sieve/engine.go` stub must be replaced with a working implementation.
Options:

**Option A (recommended)**: Implement a minimal Sieve interpreter covering the
mandatory capabilities the engine already advertises. Scope:
- `fileinto` (RFC 5228) — set destination folder
- `reject`/`ereject` (RFC 5429) — reject with DSN
- `vacation` (RFC 5230) — auto-reply (rate-limited)
- `variables` (RFC 5229) — variable substitution
- `imap4flags` (RFC 5232) — set IMAP flags on delivery
- `envelope` — test envelope (MAIL FROM, RCPT TO)
- `header` — test header values
- `body` — test body content

A minimal Sieve parser/evaluator is ~1500 lines of Go. The grammar is LL(1).
AST nodes: `IfControl`, `TestList`, `ActionCommand`, `StringList`.

**Option B**: Vendor `github.com/emersion/go-sieve` (experimental, partial RFC 5228).
Watch for: it doesn't implement all extensions; may require patches.

Either way, remove the false capability advertisement for unimplemented extensions
until they are actually working.

### 2.2.2 — Wire Sieve into the delivery pipeline
On local delivery, check if the recipient has a Sieve script stored. Load and execute
it before storing to INBOX. Script storage:
```sql
CREATE TABLE IF NOT EXISTS sieve_scripts (
    username   VARCHAR(255) PRIMARY KEY,
    script     TEXT NOT NULL,
    active     BOOLEAN DEFAULT TRUE,
    updated_at TIMESTAMP DEFAULT NOW()
);
```

### 2.3.2 — Fix JWT Bearer token validation
**File**: `internal/jmap/server.go:358-362`

```go
import "github.com/golang-jwt/jwt/v5"

func (j *JMAPServer) validateBearerToken(authHeader string) (string, bool) {
    if !strings.HasPrefix(authHeader, "Bearer ") {
        return "", false
    }
    tokenStr := strings.TrimPrefix(authHeader, "Bearer ")
    claims := &jwt.RegisteredClaims{}
    token, err := jwt.ParseWithClaims(tokenStr, claims, func(t *jwt.Token) (interface{}, error) {
        if _, ok := t.Method.(*jwt.SigningMethodRSA); !ok {
            return nil, fmt.Errorf("unexpected signing method: %v", t.Header["alg"])
        }
        return j.jwtPublicKey, nil // loaded from config at startup
    })
    if err != nil || !token.Valid {
        return "", false
    }
    return claims.Subject, true // returns username
}
```

## Phase 2.4 — SMTP Protocol Gaps

### 2.4.1 — Fix SMTP timeouts (RFC 5321 §4.5.3.2)
**File**: `internal/smtpd/server.go:109-114`

Per RFC 5321:
- EHLO/HELO reply: 5 min
- MAIL FROM reply: 5 min
- RCPT TO reply: 5 min
- DATA initiation: 2 min
- DATA block: 3 min
- DATA termination `.` reply: **10 min**

```go
s.ReadTimeout  = 10 * time.Minute
s.WriteTimeout = 10 * time.Minute
```

Note: `go-smtp` uses a single timeout pair. For granular timeouts, implement a
`net.Conn` wrapper that resets the deadline after each command.

### 2.4.2 — SPF `redirect` modifier
**File**: `internal/security/spf_dmarc.go:161-185`

In `evaluateSPF`, handle the `redirect` modifier (appears as a separate pass after
mechanism loop):
```go
// After the mechanism loop, check for redirect modifier
for _, mechanism := range parts[1:] {
    if strings.HasPrefix(mechanism, "redirect=") {
        redirectDomain := strings.TrimPrefix(mechanism, "redirect=")
        return p.evaluateSPFDomain(ctx, redirectDomain, ip, sender, depth+1)
    }
}
```
`redirect` replaces the default result and is mutually exclusive with `all`.

### 2.4.3 — DMARC full tag parsing
**File**: `internal/security/spf_dmarc.go:348-370`

Extend `parseDMARCPolicy` to return a `DMARCRecord` struct:
```go
type DMARCRecord struct {
    Policy          DMARCPolicy  // p=
    SubdomainPolicy DMARCPolicy  // sp= (defaults to p= if absent)
    AlignDKIM       string       // adkim= (r|s, default r)
    AlignSPF        string       // aspf= (r|s, default r)
    Percentage      int          // pct= (0-100, default 100)
    ReportURIsAgg   []string     // rua=
    ReportURIsForensic []string  // ruf=
    FailureOptions  string       // fo=
    ReportInterval  int          // ri= seconds
}
```

Wire `Percentage` into enforcement: if `pct=50`, only enforce on ~50% of failures
(use `hash(envelopeFrom+date) % 100 < pct` for deterministic sampling).
