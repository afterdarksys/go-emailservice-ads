# Phase 6.0 — Hardening & Observability
_Milestone: M6 | Estimated effort: 5–6 days_

## Goal
Complete the security and operational hardening: TLS-RPT reporting, DMARC aggregate
reporting, distributed cluster state sync for outbreak detection, and production
chaos testing.

---

## Phase 6.1 — Reporting (TLS-RPT + DMARC Aggregate)

### 6.1.1 — TLS-RPT (RFC 8460)
Wire `internal/security/tls_rpt.go` into actual delivery reporting:
- Record TLS negotiation failures per destination domain
- Generate daily JSON reports per RFC 8460 §4
- Send reports to `rua` address from recipient domain's `_smtp._tls` TXT record

### 6.1.2 — DMARC Aggregate Reporting (RFC 7489 §7.2)
For each domain we receive mail for:
- Record SPF/DKIM/DMARC results per sending IP per day
- Generate XML report per RFC 7489 Appendix C
- Send to `rua=` addresses in recipient domain DMARC record
- Rate limit: max 1 report per domain per day

### 6.1.3 — ARC reporting
For forwarded mail, record ARC chain results and feed into DMARC reports.

## Phase 6.2 — Distributed Cluster State

### 6.2.1 — Shared outbreak state via Redis pub/sub
Replace in-memory `FuzzyOutbreakEngine` map with Redis:

```go
type DistributedOutbreakEngine struct {
    local  *FuzzyOutbreakEngine  // fallback when Redis down
    redis  *redis.Client
    nodeID string
}

// On outbreak detection:
// PUBLISH outbreak:cluster <json: {hash, count, timestamp, nodeID}>

// Background subscriber:
// SUBSCRIBE outbreak:cluster → merge into local state
```

Each node maintains its own local state plus receives updates from peers.
Redis is optional — when unavailable, fall back to local-only detection.

### 6.2.2 — Cluster reputation sharing
Share DNSBL lookup results across nodes via Redis cache:
- Key: `dnsbl:<zone>:<ip>` → Value: `{listed: bool, score: float, ttl: int}`
- Avoids duplicate DNS queries across pods for same source IP

## Phase 6.3 — Chaos & Resilience Testing

- Kill LDAP during active auth → verify reconnect within SLA
- Kill Redis during peak load → verify local fallback, no message loss
- Flood with 10K connections → verify rate limiter, no OOM
- Inject DNS timeout → verify SPF/DKIM degrade gracefully (temperror, not fail)
- Kill Rspamd sidecar → verify async scorer skips, primary path unaffected
- Certificate expiry simulation → verify TLS renewal alerts fire
